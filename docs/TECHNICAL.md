# 기술 문서

## 디스크 구조
- 트랙 1개(MODE2/2352). 실행 파일 `SLPS_015.59`, 오버레이·데이터는 ISO9660 일반 파일(`BIN/`, `BATTLE/`, `EVBIN/`, `EVDAT/`, `DATA/`)입니다(`tools/iso.py`).
- 빌드는 파일 크기를 바꾸지 않고, 바뀐 섹터만 다시 쓴 뒤 EDC/ECC를 다시 계산합니다(`tools/disc.py`, `tools/cdsec.py`).

## 문자열
- 글자는 2바이트(리틀 엔디언) 코드, `0xFFFF`로 끝납니다. `0x100~0x15F`는 숫자·영문·기호, 그 위는 가나·한자입니다. `0x8xxx`/`0x9xxx`는 제어 코드(`{81ff}` 이름 삽입, `{80xx}` 숫자, `{83xx}` 색, `{84xx}`/`{85xx}` 위치, `{9000}` 줄바꿈, `{9100}` 버튼 대기, `{9200}` 새 페이지, `{9300}`/`{9400}` 반각 모드)입니다(`tools/tbl.py`, `tools/scan16.py`).
- `tools/extract_text.py`가 실행 파일과 모든 오버레이에서 문자열을 찾아 원래 자리의 길이(cap)와 줄 폭(w)을 함께 기록하고, 빌드는 번역문을 원래 자리에 덮어씁니다. 길이·줄 폭·제어 코드는 `tools/ko.py`로 검사합니다.
- `{81xx}`의 `xx`는 삽입하는 이름의 칸 폭(반각 단위)입니다. 도구·마법 목록은 두 칸 배치에 이름 폭 8(한글 4자)이므로, 아이템·필드 마법 이름은 4자 이내로 맞췄습니다.

## 글꼴
- `DATA/FONT.DAT`(RAM 0x8001020C부터)는 16×16 1bpp 글꼴입니다. 한글은 코드 `0x200`부터 배정하고, 글꼴 파일의 0x3C00 이후 빈 공간에 나눔스퀘어 네오로 그린 1,054자를 넣습니다.
- 실행 파일의 글자 출력 루틴(0x80052030)에서 0x800254F0의 새 함수로 점프시켜, `0x200` 이상 코드는 1bpp 글리프를 게임의 2bpp 작업 영역으로 펼쳐 그립니다. 글리프 뒤 첫 빈 코드는 반각 공백, `,.!?'"` 는 반각 글자로 그립니다(keystone으로 어셈블, `build.py`).
- 요일 코드 `0x200~0x206`은 게임이 직접 계산해 찍으므로 그 자리에 한글 요일(일~토)을 둡니다.
- 이름 입력 화면(`BIN/NAMEIN.BIN`)의 가나 표 두 장은 자주 쓰는 한글 음절 180자 표로 바꿉니다.

## 그림 글자
- 대상은 4bpp TIM입니다(`tools/tim.py`, `tools/gfx.py`).
- 나무 버튼(`wood`): 원래 글자 픽셀을 같은 행의 나뭇결 색으로 메운 뒤 원래 글자색으로 다시 씁니다. 상점·은행·교회·여관·성·마을·카지노 버튼과 상점 간판.
- 전투 커맨드 시트(`BATTLE/B_CMD.BIN`): 공격/방어/항복, 카운터·필살, 「어느 걸로?」, 특기 35종·마법 55종 이름. 3자 이하는 갈무리11, 4자는 갈무리9.
- 은행 「예금」, 성 「도카폰성」, 아이템점 「감정」 현수막처럼 테두리·그림자가 있는 간판은 원래 색 번호를 유지하며 다시 그립니다.
- 보드 지도의 마을 이름 간판(`DATA/F_00_FD.DAT` 안 헤더 없는 4bpp 시트), 장 제목 10종(`DATA/S_TITxx.DAT`), 오프닝 문장(`EVDAT/EVOP.DAT`), 타이틀 메뉴·캐릭터 선택 화면(`BIN/INTROPI.DAT`).

## 검증 도구
- `tools/emu.py`, `tools/d.py`: DuckStation을 백그라운드로 띄워 GDB 원격 접속으로 메모리를 읽고 쓰고, 키 입력·스크린샷을 자동화합니다.
- `tools/mdis.py`, `tools/sjscan.py`, `tools/dump.py`: 코드·문자열 조사.
